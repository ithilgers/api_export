## [1.0.0] - 2026-11-18

### Added
- Token-secured JSON feed under `/api/v1/{resource}` (path prefix configurable), detected below the base of the site and its language: with or without language prefix and in subdirectory installations
- Feed generated directly by a middleware (after the site resolution, before user authentication and page resolution), without TSFE, TypoScript or plugin; independent of type and access settings of the root page
- Resources `events` (sf_event_mgt 7/8) and `news` (georgringer/news 12/13); further record types via tagged provider classes
- API clients with active flag and validity period; the token is sent as HTTP header (`X-Feed-Token` by default)
- Tokens are generated by the system (64 hexadecimal characters) and shown only once, in the backend form or via the CLI command `api-export:client:token <uid>`; only the SHA-256 hash and the last 4 characters are stored (unique)
- Copied clients (also as part of a copied page) are deactivated and get an unknown token; clients, grants and detail page mappings can only be managed by admins
- Per-client grants per resource: storage folders (optionally recursive), categories with OR/AND/NOT OR/NOT AND and optional subcategories, maximum number of items, resource-specific settings (display mode, sorting, archive); each resource is offered once per client, otherwise the first grant by sorting applies
- Visibility like a public list for anonymous visitors: hidden, scheduled, access-restricted, deleted and workspace records as well as protected storage folders are never delivered; frontend or backend logins in the request change nothing
- Detail links via the router of the target site, per storage folder and inherited by subfolders, with a fallback detail page per grant; empty if the page is not reachable for anonymous visitors. News of the type "internal page" or "external URL" link to their target
- Pagination via `page` and `limit` with `total`, `pages` and `count` in the response
- `ModifyFeedItemEvent` (PSR-14) to adjust or extend each item, with access to the request; listeners may abort with their own response
- Consistent JSON responses (200, 400, 401, 403, 404, 405, 429, 500), each with `Content-Type: application/json; charset=utf-8`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff` and `X-Robots-Tag: noindex, nofollow`; only `GET` and `HEAD`
- Limit of requests without a valid token per IP address (`failedAttemptsLimit`, `failedAttemptsInterval`), answered with `429` and `Retry-After`; requests with a valid token are never blocked; throttled logging without the token
- English and German backend labels
- Unit and functional test suite (SQLite and MariaDB/MySQL)
- Compatible with TYPO3 12.4 LTS
